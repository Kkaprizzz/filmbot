# BotoHub: обязательные подписки FILMWORKS

Контракт проверен по официальной документации: https://botohub.me/integration.

Используется `POST https://botohub.me/get-tasks-extended` с заголовком `Auth` и
JSON `chat_id` (ID нажавшего пользователя), `only_has_check: true`.
`max_op` не передаётся: число спонсоров берётся из настроек самого бота в BotoHub.
Возраст, пол и другие дополнительные данные не отправляются.

Спонсоры показываются кнопками, выполненные отмечены ✅. Кнопка «Проверить подписки»
всегда делает свежий запрос и после успешной проверки открывает главное меню.
Регистрация в базе использует ID пользователя, а не автора сообщения с кнопкой — бота.
Незавершённый запрос фильма после проверки нужно отправить заново.

Middleware установлен до фильтров и обработчиков всех сообщений и callback query
в личных чатах. Он закрывает `/start`, поиск, коллекцию, админку и ранее отправленные
кнопки. Исключений для администраторов нет. Групповые сообщения не обслуживаются,
чтобы они не давали обход проверки. Пользователь учитывается в статистике уже при
первом обращении, даже если ещё не завершил подписки.

Доступ разрешается только при настоящем boolean `completed: true` или `skip: true`.
`skip` означает отсутствие спонсоров согласно контракту BotoHub.
Пустой `{ "tasks": [] }` без флагов, неверный ответ, HTTP 400/401/429/5xx и сетевой
сбой доступ не открывают: показывается кнопка повторной проверки.
Флаг `fake` отдельно не используется для блокировки; решение остаётся за
`completed`/`skip`, как описано в документации.

Успешные проверки кэшируются на 30 секунд, невыполненные — на 3 секунды.
Явная проверка кнопкой обходит кэш. Кэш ограничен 4096 пользователями, запросы одного
пользователя сериализованы. После неудачной перепроверки старый успех не используется.
Кэш находится в памяти и сбрасывается при перезапуске; проверки не дают бессрочный доступ.
Документация BotoHub указывает время привязки спонсоров 3 минуты: после истечения
привязки сервис может назначить новые подписки.

## Настройки

В локальном и серверном `.env`:

```dotenv
BOTOHUB_TOKEN=replace_with_integration_token
BOTOHUB_CACHE_SECONDS=30
```

Без токена новая версия не запускается. Токен имеет тип `SecretStr`, не хранится в Git,
не выводится в логи и исключён из образа через отслеживаемый `.dockerignore`.
Никакие тела ошибок API и заголовки авторизации не логируются. Редиректы API не
поддерживаются, чтобы не передавать заголовок авторизации другому серверу.

## Проверка и деплой

```bash
python -m pip install -r requirements-dev.txt
pytest -q
```

Тесты используют локальный HTTP-сервер BotoHub и тестовый транспорт Telegram;
настоящие подписки и продакшен-база в тестах не затрагиваются. Проверяются контракт
авторизации, все статусы, повреждённые ответы, таймауты, кэш, параллельные запросы,
вход через меню и старые кнопки, ошибки редактирования сообщения и правильный ID пользователя.

GitHub Actions сначала выполняет тесты на Python 3.11 (как в Docker), затем деплоит
ветку `main` в `Kkaprizzz/filmbot`. Перед первым деплоем токен должен быть установлен
на myvps в `/root/filmbot/.env`. `docker compose up -d --build` сохраняет текущие
контейнеры до успешной сборки, база и её volume не удаляются.
